# Пилот «Пульса»

## Сценарий пользователя

1. HR добавляет стажёра, выбирает команду и наставника. Для личного кабинета HR может указать идентификатор `sub` из корпоративного SSO. Пульс открывает обе анкеты первого месяца. Следующие пары открываются по месячному графику новой стажировки, всего шесть пар.
2. Стажёр и наставник отвечают в личном кабинете. Перед отправкой видят, кто получит доступ к ответу. Из анкеты можно отдельно написать команде HR. По запросу наставника модель предлагает вопросы, чтобы уточнить его комментарий. Для внешнего опроса HR копирует персональные ссылки Tally из карточек контрольных анкет. Ссылка привязана к одному назначению и действует до срока ответа, максимум 32 дня.
3. Новый ответ меняет покрытие, динамику и светофор на основном HR-обзоре. Красный статус учитывает явную просьбу о помощи. Карточка показывает сигнал, период, цитату и исходный ответ.
4. Фоновая задача передаёт историю двух сторон настроенной модели. HR получает сводку с проверяемыми фрагментами и предложением следующего шага. При исправлении анкеты вывод пересчитывается. HR сохраняет свой шаг и отмечает его выполнение.
5. HR может напомнить из обзора за выбранный месяц. За 48 часов до срока «Пульс» автоматически показывает напоминание в личном кабинете участника, от которого ещё ждём ответ. Кнопка ведёт на его назначение. После ответа напоминание скрывается.
6. После двух ответов шестого месяца или истечения шести месяцев HR открывает редактируемый итог для финальной встречи. В нём есть прогресс, открытые вопросы и следующие шаги.
7. HR при необходимости привязывает карточку кандидата из Huntflow. Кадровая история и резюме открываются в системе подбора. Пульс хранит идентификатор привязки.

## Решения по продукту

В основе сценария персональные ссылки на контрольные опросы, раздельные перспективы стажёра и наставника, история периодов и решение HR с основанием. В исследовании обратной связи и адаптации в Яндексе этому соответствуют персонализированный сбор по этапам, итоговая сводка из нескольких отзывов и связь с системой найма.

После пилота можно отдельно оценить доставку напоминаний по почте, согласование итогового отчёта и его передачу в кадровую систему. Диагностика 360°, калибровки, внутренний бот и цепочка найма относятся к отдельным сценариям. ИИ отвечает за подготовку разговора и шаг поддержки. Решения о переводе и найме принимает человек в кадровом процессе компании.

## Окружение пилота

- Разверните чистую базу PostgreSQL и примените `go run ./cmd/migrate` из `backend`. Режим `PULSE_MODE=production` проверяет RSA-подпись RS256, `iss`, `aud`, срок действия и сопоставление `sub` с участником. Для изменений API сверяет `Origin` с адресом портала.
- На входе используйте корпоративный OIDC-шлюз. Он передаёт ID token через `Authorization: Bearer …` до Go API. Браузер работает с фронтендом и API на одном origin. Для Next.js задайте `NEXT_PUBLIC_API_MODE=remote`. При смене ключа провайдера обновите PEM в конфигурации API. Пример шлюза описан в [документации OAuth2 Proxy](https://github.com/oauth2-proxy/oauth2-proxy/blob/master/docs/docs/configuration/overview.md).
- При первом запуске API читает локальный `PULSE_BOOTSTRAP_FILE`. Храните файл рядом с конфигурацией окружения. Используйте ID команды и участников вашей организации. Пример ниже содержит вымышленные значения. Исторические ответы можно загрузить через XLSX/CSV после добавления соответствующих стажировок.
- В режиме `demo` API по-прежнему загружает учебную историю и поддерживает переключатель ролей. Для демонстрации интеграций используйте отдельную базу и тестовые ответы.

  "cohort": {"id": "pilot", "name": "Пилот", "program": "Пульс"},

### ИИ

Задайте `PULSE_AI_ENDPOINT` с полным адресом совместимого с Chat Completions API, `PULSE_AI_MODEL` и при необходимости `PULSE_AI_TOKEN`. Модель должна возвращать JSON по запросу `response_format: {"type":"json_object"}`. Для пилота с реальными анкетами используйте endpoint, утверждённый компанией для обработки HR-данных. Прототип передаёт комментарии и оценки по месяцам, роль респондента и технический ID ответа. Резюме и журнал Huntflow в запрос модели не попадают.

Go запускает фоновые задачи вместе с API, хранит попытки и результаты в PostgreSQL. При сбое выполняет до четырёх попыток с паузами. HR может повторить исчерпанную задачу из карточки. Вывод проходит проверку дословных фрагментов и ID ответов. Правила и светофор доступны независимо от модели.

### Tally

1. Создайте две формы по структуре анкет МГТС. Для шкал используйте Linear Scale 1–5, для комментариев — длинный текст. Для сопоставления используйте формулировку вопроса из «Пульса», заголовок исходной таблицы или код показателя.
2. Перед отправкой покажите получателей ответа. Для стажёра это HR, пользователи с ролью руководителя и закреплённый наставник. Для ответа наставника укажите, что его также увидит стажёр. Текст размещает владелец внешних форм в Tally.
3. В каждую форму добавьте скрытое поле `pulse_invite`. Подключите вебхук `https://<api>/api/v1/integrations/tally/webhook` с одним signing secret для обеих форм. Для персональных ссылок задайте отдельный ключ `PULSE_INVITE_KEY`.
4. Заполните `PULSE_TALLY_INTERN_FORM`, `PULSE_TALLY_MENTOR_FORM`, `PULSE_TALLY_SECRET` и `PULSE_INVITE_KEY` из настроек окружения. HR получит ссылки в карточке контрольной анкеты. Один ответ закрывает назначение. Повторная доставка с тем же ID учитывается один раз. Подпись проверяется до разбора события. [Документация вебхуков Tally](https://tally.so/help/webhooks) · [Скрытые поля](https://tally.so/help/hidden-fields)

### Huntflow

Задайте `PULSE_HUNTFLOW_ACCOUNT` и действующий `PULSE_HUNTFLOW_TOKEN`. Чтобы открыть карточку из Пульса, укажите `PULSE_HUNTFLOW_WEB_URL=https://huntflow.ru/my/<workspace>`. HR вводит ID кандидата в карточке стажёра. Пульс читает позицию и недавние записи с комментариями, показывает ссылку на карточку по последней вакансии и сохраняет только ID кандидата. Токен обновляется на стороне оператора окружения. [Huntflow API v2](https://api.huntflow.ru/v2/docs)

## Приёмка

1. Добавить тестового участника. На HR-обзоре видны два ожидаемых ответа.
2. Заполнить обе внешние формы с разными оценками понятности задач и явной просьбой о помощи в ответе стажёра. Повторная доставка того же вебхука не должна увеличить покрытие.
3. На основном HR-обзоре найти участника по сигналу. В карточке проверить красный статус, обе оценки, исходную цитату, обновлённую ИИ-сводку и следующий шаг.
4. Сохранить шаг как HR, перезайти в приложение и убедиться, что шаг сохранился. Проверить, что участник не может открыть чужую карточку и HR-сводку.
5. Привязать учебную карточку Huntflow, проверить открытие в системе подбора и восстановление экрана после временного сбоя ATS.
6. Создать напоминание из HR-обзора, открыть персональную анкету получателя и проверить исчезновение напоминания после ответа. Из анкеты написать HR и проверить доступ к обращению.
7. Проверить уточняющие вопросы в черновике наставника. После шестого месяца открыть итог стажировки, отредактировать его и проверить сохранение.
