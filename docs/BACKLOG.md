# Backlog

## Зафиксировано заранее

1. Автоматическое закрытие сигнала только из-за улучшения числовой метрики.
2. Микросервисное разбиение и отдельный брокер сообщений без измеренной потребности.

## Идеи из первого UX-ревью

1. Персональные подписки и дайджесты по сигналам, анкетам и просроченным действиям во внешних каналах.
2. Библиотека типовых действий и playbook для повторяющихся проблем стажировки.
3. Сравнение команд и потоков с анонимизацией и минимальным размером выборки.
4. Оценка эффективности действий по последующим волнам и результатам review.
5. Конструктор сохранённых отчётов с настраиваемым составом и расписанием экспорта.

## Идеи из проверки собранного приложения

1. Аннотации изменений программы на графике волн: связывать динамику со сменой формата наставничества, правил доступа и других решений.
2. Массовый триаж сигналов: назначение владельца, срока и статуса нескольким выбранным сигналам с подтверждением и историей.
3. SLA и эскалация просроченных действий: очередь по владельцам, просрочка и контроль нагрузки ответственных.
4. Preview калибровки: до фиксации показывать изменение распределения и записи без обязательных данных.

Текущие замечания по приоритету сигналов, мобильному порядку блоков, touch-целям, значениям графика и состояниям review относятся к обязательной полировке, а не к backlog.


## Техническое развитие после хакатона

1. SSO/JWT вместо демонстрационного выбора actor ID и серверная привязка пользователя к области доступа.
2. Внешний LLM-provider вместо детерминированного локального, с оценкой качества и безопасности HR-данных.
3. Production-подписи webhook и реальные адаптеры внешних сервисов вместо mock.
4. Reporting-проекция из JSONB-агрегата в нормализованные таблицы для расширенной аналитики.
5. Сохранение `due_at` и напоминаний для запросов отзывов.
6. Полноценные настройки coverage/email/compact mode в общем backend-контуре.
