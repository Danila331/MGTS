# План проверки MGTS Internship Intelligence

## 1. Автоматические проверки

- `cd backend && go test ./... && go vet ./...`
- `cd web && npm run typecheck && npm run lint && npm run build`
- `./scripts/smoke.sh` при запущенном API.
- Повторный webhook с тем же external ID не меняет число ответов.
- PostgreSQL: миграции применяются на пустой базе, повторный запуск безопасен.

## 2. RBAC

### HR

- Видит всех стажёров и все команды.
- Может создавать анкеты, назначать действия, менять настройки и проводить review.

### Руководитель

- В списке только стажёры своей команды.
- Прямой запрос чужой стажировки возвращает 403/404 без утечки данных.
- Может обновлять назначенные действия и review своей команды.

### Наставник

- Видит только закреплённых стажёров.
- Не может открыть чужую стажировку по прямой ссылке.
- Может отвечать на анкеты и обновлять назначенные действия.

### Стажёр

- Видит только свою карточку, анкеты, самоотзыв и развитие.
- Отзывы о нём доступны только при включённой HR-настройке.
- После выключения настройки отзывы исчезают и из API.

## 3. Сквозной сценарий анкеты

1. HR создаёт черновик анкеты с текстовым и шкальным вопросами.
2. Назначает аудиторию и публикует анкету.
3. Респондент открывает форму, частично заполняет её и обновляет страницу: черновик сохранён.
4. Отправляет обязательные ответы.
5. Покрытие и ответы обновляются без перезапуска.
6. Дашборд и карточка стажировки показывают новые данные.
7. При проблемном ответе появляется/обновляется сигнал с доказательствами.
8. Повторная отправка не создаёт непредусмотренный дубль.

## 4. Сигнал и действие

1. HR открывает очередь и выбирает сигнал.
2. Видит причину, срочность, силу доказательств, цитаты и динамику.
3. Подтверждает сигнал, назначает владельца и срок.
4. Создаёт действие.
5. Владелец видит его в своём кабинете и фиксирует результат.
6. HR вручную закрывает сигнал; история сохраняется.
7. Отклонение требует понятного статуса/причины.

## 5. Обратная связь и AI

- Создание черновика, публикация, входящие/исходящие.
- Запрос отзыва и рекомендации респондентов.
- AI-анализ самоотзыва и обоснования руководителя.
- Генерация итогового отзыва с возможностью редактирования.
- AI-редактор выделенного текста.
- AI-запрос содержит проверяемые evidence и учитывает область актора.
- Автономный provider работает без внешних ключей.

## 6. Review, диагностика, развитие

1. Стажёр отправляет самоотзыв.
2. Руководитель добавляет обоснование и использует AI.
3. HR выполняет калибровку и объявляет результат.
4. Стажёр видит объявленный результат.
5. Создание 180/270/360 формирует правильные роли и кворум.
6. Завершение диагностики показывает результат.
7. Цель развития создаётся, обновляется и отображается в карточке стажировки.

## 7. Интеграции

- Mock sync каждого источника обновляет статус и журнал.
- Ошибка синхронизации видна и допускает повтор.
- Внешний ответ нормализуется и попадает в общую аналитику.
- Данные задач/календаря доступны как контекст отзыва.

## 8. Визуальная проверка

Проверить `/dashboard`, `/interns`, `/interns/[id]`, `/surveys`, `/surveys/[id]`, `/surveys/[id]/take`, `/signals`, `/reviews`, `/me` и `/ai`:

- соответствие каркаса, токенов, типографики и компонентов `mts-ai`;
- светлая и тёмная темы;
- 1440 px, 1024 px, 768 px и 375 px;
- отсутствие горизонтального overflow;
- клавиатура, focus, touch-цели и reduced motion;
- loading, empty, error, forbidden, insufficient-data и success;
- нет мёртвых кнопок и заглушек;
- после мутации интерфейс обновляет связанные данные.

## 9. Финальное демо

1. HR-обзор: проблема в программе.
2. Карточка стажёра: негативная динамика и расхождение ролей.
3. Сигнал: доказательства и назначение действия.
4. Наставник: выполнение действия.
5. Новая анкета: положительное изменение.
6. AI: итоговый отзыв и план развития.
7. Review: калибровка и объявление.
8. Стажёр: результат, разрешённые отзывы и следующие шаги.
